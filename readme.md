# 二维码文件传输工具

用于无网络环境，通过屏幕展示二维码、再由另一台设备拍摄图片或视频来传递文件。项目是 Java 8 + Maven + Swing 桌面应用，无需服务端。

## 当前能力

- 发送端直接生成新版四码图片：每张 1080×1080 图片最多放置 4 个 500×500 二维码，并带有角落定位标记。不会生成中间单码图片，也不会自动生成视频。
- 接收端支持旧协议单码图片、旧协议单码视频，以及新版四码图片/视频。旧版接收程序不能解析新版四码合图。
- 新版传输清单使用 `QRF2` 标识，记录页数、文件字节数、SHA-256 和原文件名；数据页仍沿用旧页协议（4 位页号 + 每页最多 1020 个 Base64 字符），以兼容旧版数据页解析逻辑。
- 新协议出现缺页、页数不符或 SHA-256 不符时，不会输出恢复成功文件。旧协议没有文件名和整文件哈希，能做的完整性判断较弱。
- 当前单文件上限为 7 MiB（7×1024×1024 字节），由四位页号可表达的最多 10,000 页约束。二维码页数公式为 `ceil((4×ceil(S/3)+10)/1020)`，其中 `S` 是文件字节数；1 MiB 文件约需 **1,371 页**，不是 1,361 页。四码图片可把每 4 页排在同一帧中，但并不减少逻辑数据页数。

## 使用方法

### 发送文件

1. 点击“选择文件并生成四码图片”。
2. 图片结果目录在所选源文件的同级目录，名称由原文件名（不含扩展名）和生成时间组成。
3. 生成完成后，发送文件区域显示图片目录，可打开目录或播放图片；完成弹窗也提供“立即播放”。

### 接收二维码图片

选择包含二维码图片的文件夹。旧版单码图片按原流程解析；新版单码数据图片需要连同 `transfer_manifest.txt` 保留。恢复产物写入所选图片文件夹旁边、带输入目录名和时间戳的结果目录。

### 接收二维码视频

选择手机录制的视频。程序流式读取视频帧，不把整段视频拆成 PNG 文件落盘。视频结果、缺页报告和可供补拍的 `recognized_qr` 目录写入视频旁边、以原视频文件名开头并附时间戳的结果目录。新版传输应使用新版接收端；尽量传递手机原片，避免聊天软件二次压缩。

识别完成后如果仍有缺页，程序不会拼出可能错位的文件。视频中的补采会针对缺页与相邻已识别页之间的时间窗口逐帧扫描，并尝试整帧及四个象限的二维码；补采失败只能说明本次解码没有取得有效页，不能据此断言该二维码一定没有拍入视频。开头或结尾缺页缺少一侧时间锚点，扫描范围会受边界策略限制。

### 播放四码图片

播放开始前有 3 秒倒计时，播放结束会提示。默认每张停留 200 毫秒（每秒 5 张），可在“播放速度”中设置 200–10,000 毫秒，也可在播放窗口临时调整。播放器预加载下一张，并按当前图像实际显示时间推进；遇到读取或界面卡顿时会延长当前图片停留，不会为了追赶进度而跳过图片。

## 配置与输出位置

- “目录设置”用于设置文件选择窗口的默认起始目录；它不决定输出产物位置。当前实现会将这个起始目录用于发送和接收文件选择窗口。
- 发送四码图片输出到源文件同级；图片接收和视频接收的恢复产物输出到相应输入的同级目录。
- 播放速度单独配置，设置保存在当前用户目录下的 `.qrcode-forwin/settings.properties`。

## 限制与拍摄建议

- 每帧二维码比传统单码更小，识别效果依赖屏幕缩放、拍摄距离、对焦、运动模糊和视频压缩；四码布局不等于四倍端到端传输速度。
- 200 毫秒是本地播放器对每张图片的最短计划停留时间，不代表相机曝光、显示器刷新和视频编码一定完整记录了每张图片。正式传输前建议小文件实拍验证，必要时降低播放速度。
- Java 运行环境使用 Java 8。视频处理依赖系统 FFmpeg：macOS 可用 `brew install ffmpeg` 安装；Windows 请将 `ffmpeg.exe` 加入 `PATH`，或启动时通过 `-Dqrcode.ffmpeg.path=完整路径` 指定。

## 开发与构建

### macOS Apple Silicon

```bash
mvn clean package
```

### Windows x64

```powershell
mvn -Djavacpp.platform=windows-x86_64 clean package
```

生成的可运行 jar 位于 `target/` 目录。应用通过 `com.example.qrcode.demo.FileTransferApp` 启动。
